# 내 기금·복지 조회 앱 — 설치·운영 안내

직원이 휴대폰에서 **이름 + 비밀번호**로 로그인해 본인의 **기금 대여잔액·이번 달 공제액**과 **선택적복지비 배정·분기별 사용·남은 금액**을 확인하는 앱입니다. 화면 위쪽 탭으로 두 가지를 오갑니다.

```
[총무 PC] 기금대여관리시스템_직원앱연동.html
   └ 📱 직원앱 연동 → "게시하기" : 직원별 계산 결과만 업로드
              ↓
        [Firebase] 직원별 문서 (본인만 읽기 가능)
              ↓
[직원 휴대폰] 이 폴더(fund/)의 앱 → 로그인 → 내 잔액·공제액
```

- 아이디: **본인 이름** (예: 홍길동)
- 초기 비밀번호: **생년월일 6자리** (예: 900115)
- 첫 로그인 때 새 비밀번호(8자 이상, 영문+숫자)로 바꾸지 않으면 조회할 수 없습니다.
- 계산은 총무 PC의 기존 기금대여관리시스템이 그대로 합니다. 앱에는 결과만 올라갑니다.

---

## 1. Firebase 준비 (처음 한 번, 약 15분)

1. <https://console.firebase.google.com> 접속 → **프로젝트 추가**
   - 이름: 예) `asudi-fund` / Google 애널리틱스: 사용 안 함
2. 왼쪽 메뉴 **빌드 → Authentication → 시작하기**
   - 로그인 방법 탭 → **이메일/비밀번호** → 사용 설정 → 저장 (이메일 링크는 끄기)
3. Authentication → **사용자** 탭 → **사용자 추가** (총무 관리자 계정)
   - 이메일: `fund-admin@fund.asudi.co.kr` ← 정확히 이대로
   - 비밀번호: 총무만 아는 강한 비밀번호
4. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
   - 위치: 현재 프로젝트는 `nam5`(미국 멀티 리전)로 만들어져 있습니다. 위치는 바꿀 수 없으며, 동의서의 국외 이전 안내도 미국 기준으로 작성되어 있습니다. / **프로덕션 모드**로 시작
   - **규칙** 탭 → 내용을 모두 지우고 이 폴더의 [`firestore.rules`](firestore.rules) 내용을 붙여넣기 → **게시**
5. 톱니바퀴 → **프로젝트 설정 → 일반 → 내 앱 → 웹(`</>`) 아이콘**
   - 앱 닉네임: `기금조회` (Hosting 체크 안 함) → 앱 등록
   - 화면에 나오는 `const firebaseConfig = { ... };` 부분을 복사해 둡니다.
6. Authentication → **설정 → 승인된 도메인**에 `asudi-fund.web.app`이 있는지 확인 (보통 자동으로 들어가 있음)

## 1-1. 앱 주소(asudi-fund.web.app) 자동 배포 설정 (처음 한 번)

직원 앱은 **https://asudi-fund.web.app** 에서 열립니다. main 브랜치에 `fund/` 변경이 합쳐지면 GitHub가 자동으로 Firebase Hosting에 올립니다(`.github/workflows/firebase-hosting.yml`).

1. Firebase 콘솔 → 왼쪽 **빌드 → Hosting → 시작하기** → 안내 화면은 **다음**만 눌러 끝까지 진행 (명령어 입력은 하지 않아도 됨)
2. 톱니바퀴 → **프로젝트 설정 → 서비스 계정** 탭 → **새 비공개 키 생성** → JSON 파일이 내려받아집니다.
   - 이 파일은 **비밀번호와 같습니다.** 아래 3번에 넣은 뒤 PC에서 지우고, 메일·메신저로 보내지 마세요.
3. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `FIREBASE_SERVICE_ACCOUNT`
   - Secret: 2번 JSON 파일을 메모장으로 열어 **내용 전체**를 붙여넣기 → Add secret
4. 저장소 **Actions** 탭 → "직원 앱 배포 (Firebase Hosting)" → **Run workflow** → 초록 체크가 뜨면 https://asudi-fund.web.app 접속 확인

## 2. 설정값 넣기

- **직원 앱**: [`firebase-config.js`](firebase-config.js)에 `asudi-fund` 프로젝트 설정값이 들어 있습니다.
  (이 값은 공개돼도 괜찮습니다. 데이터 보호는 보안 규칙이 담당합니다.)
- **총무 PC**: `기금대여관리시스템_직원앱연동.html`에도 같은 값이 들어 있어 따로 입력할 필요가 없습니다.
  프로젝트를 바꾸게 되면 두 곳을 모두 고쳐야 합니다.

## 3. 직원 계정 만들기 (처음 한 번)

1. 총무 PC 화면 → 📱 직원앱 연동 → ② 관리자 비밀번호로 로그인
2. ⑤ **조직도 엑셀**(Amaranth 조직도 내보내기 파일) 선택
   - 대여 중인 직원만 골라서 "생성 예정 / 계정 있음 / 생년월일 없음"을 보여 줍니다.
3. **계정 만들기** 클릭
   - 대상: 기금 대여자 + 선택적복지비 대상자. 복지비 대상자까지 만들려면 먼저 ④에서 복지비 엑셀을 한 번 읽어 주세요.
4. 조직도에 없거나 생년월일이 빈 직원은 ⑥ **개별 계정 만들기**로 이름과 생년월일 6자리를 직접 넣어 만듭니다.

## 3-1. 앱의 대여 정보 표시와 대여월 확인표

- 건마다 **대여 → 상환 시작(주택은 원금상환 시작) → 상환 완료 예정** 월을 보여 주고, 카드 위에 상환 원칙을 표시합니다(생활안정자금 대여기준·주택자금 대여기준 2026.4.20. 개정 기준).
- **대여월 계산**: 규정상 "대여일 이후 최초 급여지급일부터 상환"이므로
  - 생활안정자금 = 상환시작월 − 1개월
  - 주택자금 = 원금상환 시작월 − 37개월 (3년 거치 후 차월부터 상환)
  - 육아휴직으로 밀린 개월 수는 되돌립니다. (시스템의 `loanY/loanM` 값은 ✏️ 수정 때 그날 달로 바뀌어 쓰지 않습니다.)
- **대여월 확인표** (총무 PC → 📱 직원앱 연동 → ③-1): 모든 대여 건의 계산된 대여월을 보여 줍니다.
  - 주택자금 원금이 5백만원 단위가 아닌 건(추가대여 합산, 정년 분할 등)은 **확인 필요**로 표시되고, 확인 전에는 앱에 대여월이 "-"로 나옵니다.
  - 월을 고치거나 "이 값이 맞음"에 체크한 뒤 [저장]하면 **확정**됩니다. 확정값은 총무 PC 브라우저에 저장되며, ③ 게시 때 반영됩니다.
  - 추가대여로 합산된 건은 **추가대여** 칸에 월을 넣으면 앱에 "2017년 5월 / 추가 2020년 5월"처럼 함께 표시됩니다.
  - 2016~2022년 월별 상환 시트와 대여 심의 이력으로 확인한 12건(주택)은 **확정(자료 확인)** 값이 미리 들어 있습니다. 김홍석·최한겸은 추가대여, 이수근·이만희·심재혁·김세준(2건차)·최용복은 정년 분할로 거치 없이 바로 상환한 건입니다.
- **상환 완료 예정**: 기금대여관리시스템의 계산을 한 달씩 진행해 잔액이 0이 되는 달입니다(육아휴직 기간 반영).

## 4. 매달 할 일

1. 총무 PC 화면에서 연월을 공제 월로 맞추고 금액을 확인합니다.
2. 📱 직원앱 연동 → ③ **게시하기**
   - 직원 앱에 "2026년 10월 급여 공제 예정액"처럼 그 달 기준으로 표시됩니다.
   - 상환이 끝나 목록에서 빠진 직원은 "현재 대여 중인 기금이 없습니다"로 바뀝니다.

## 4-1. 분기마다 할 일 (선택적복지비)

1. 분기 집행이 끝나면 선택적복지비 관리 엑셀(예: `2026년 선택적복지비.xlsx`)을 저장합니다.
2. 📱 직원앱 연동 → ④ 에서 그 파일을 선택합니다.
   - `안산도시개발(N분기)`, `촉탁직(N분기)` 시트(차수 `_1차`, `_2차` 포함)를 자동으로 읽습니다.
   - **배정액** = 1분기 1차 시트의 "총금액", **분기별 사용** = 그 분기 시트들의 "지급계" 합계, **남은 금액** = 배정 − 사용
   - 미리보기 표에서 금액을 확인합니다. 아직 시트가 없는 분기는 앱에 "집행 전"으로 나옵니다.
3. **복지비 게시하기**를 누릅니다.

※ 시트 이름 형식(`안산도시개발(3분기)`, `촉탁직(1분기)_2차`)과 열 위치(B 성명, C 총금액, H 지급계)를 바꾸면 읽지 못합니다.

## 6. 비밀번호를 잊은 직원 (비밀번호 초기화)

총무 PC → 📱 직원앱 연동 → **⑥ 비밀번호 초기화**에 이름을 넣고 버튼을 누르면 30초~1분 뒤 **임시 비밀번호**(영문+숫자 8자리)가 나옵니다. 직원에게 전달하면, 직원은 임시 비밀번호로 로그인한 뒤 새 비밀번호를 정합니다. 개인정보 동의 기록과 대여·복지비 정보는 그대로 유지되고, 그 직원이 로그인해 있던 기기는 로그아웃됩니다.

- 실제 처리는 GitHub Actions의 "직원 비밀번호 초기화"(`.github/workflows/reset-password.yml`)가 배포용 서비스 계정(`FIREBASE_SERVICE_ACCOUNT`)으로 합니다.
- **처음 한 번 GitHub 연결 설정**이 필요합니다. ⑥의 [GitHub 연결 설정]을 누르고 안내대로 토큰을 만들어 붙여넣습니다.
  - GitHub → 프로필 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens → Generate new token**
  - Repository access: **Only select repositories** → `ikwondoes-blip/-`
  - Repository permissions: **Actions: Read and write** (나머지는 No access)
  - 만료일이 지나면 같은 방법으로 새 토큰을 만들어 다시 저장합니다.
- 토큰은 총무 PC 브라우저에만 저장됩니다. 담당자가 바뀌면 [저장된 토큰 지우기]를 누르고 GitHub에서 토큰을 삭제하세요.
- 이 저장소는 공개 저장소이므로 GitHub Actions 실행 기록에 직원 계정 ID(u…)가 남습니다. 임시 비밀번호는 기록에서 가려지며, 직원이 첫 로그인 때 바로 바꿉니다.

## 7. 개인정보 동의

- 직원은 **첫 로그인 때** 개인정보 수집·이용, 처리위탁(Google Firebase), 국외 이전 안내를 보고 두 항목에 모두 동의해야 조회할 수 있습니다. 동의하지 않으면 조회 없이 안내 문구만 보입니다.
- 동의 기록(버전·서버 시각)은 각 직원 문서의 `consentVer`, `consentAt`에 남습니다.
- **확인 방법:** 총무 PC → 📱 직원앱 연동 → **⑦ 직원별 개인정보 동의 현황 → 현황 불러오기**. 직원별 동의 상태(동의 / 미동의 / 재동의 필요)와 동의 일시, 비밀번호 변경 여부가 표로 나오고, **엑셀로 저장**하면 동의 기록부로 보관할 수 있습니다.
- 동의 문구(보유 기간 등)를 바꾸면 `fund/index.html`의 `CONSENT_VER` 값을 올려 주세요. 모든 직원에게 다시 동의를 받습니다. 총무 PC 파일의 `FA_CONSENT_VER`도 같은 값으로 맞춰야 ⑦ 현황이 정확합니다.
- 동의 철회 요청이 오면 6번(계정 삭제)과 Firestore `members`에서 그 직원 문서 삭제를 해 주세요.
- 회사/기금의 **개인정보 처리방침**에도 수탁자 "Google LLC(Firebase)"와 국외 이전 내용을 추가해 두세요.

## 8. 보안 메모

- 직원은 **자기 문서만** 읽을 수 있습니다. 다른 사람 문서 읽기, 전체 목록 조회, 금액 수정은 서버에서 막습니다.
- 문서마다 계정 고유번호(uid)가 묶여 있어서, 다른 사람이 같은 이름으로 먼저 가입해도 데이터를 볼 수 없습니다.
- 초기 비밀번호(생년월일)는 동료가 짐작할 수 있습니다. 계정을 만든 뒤 **빨리 첫 로그인을 하도록 공지**해 주세요. 비밀번호를 여러 번 틀리면 Firebase가 잠시 로그인을 막습니다.
- 앱 코드(이 폴더)에는 직원 정보가 들어 있지 않습니다. 직원 정보가 들어 있는 **총무 PC용 HTML 파일은 저장소에 올리지 마세요.**
